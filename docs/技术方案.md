# EasyVIEW 技术方案（极简预览版）

## 1. 定位

EasyVIEW 是一个**极简视频监控预览客户端**：只做「把摄像头上墙看画面」这一件事。
技术栈 PyQt6 + LibVLC，跨 Windows / Linux。

刻意**不做**（相比早期全功能版本）：ONVIF 发现、PTZ、录像/回放、抓拍、录像计划、
移动侦测、厂商 SDK 巡航、电视墙分页等。全功能实现保留在 git 分支 `archive/full-feature`。

## 2. 模块结构

```
main.py                 入口；Linux 检测到 DISPLAY 时强制 QT_QPA_PLATFORM=xcb
core/
  config.py             数据目录、VLC 运行时定位/注入、LibVLC 启动参数
  crypto.py             Fernet 加密凭据；密钥存 OS 凭据库，回退受限密钥文件
  database.py           SQLite：cameras 表（含迁移）
  camera.py             Camera 模型 + CRUD + 连接测试
  rtsp_templates.py     多厂商 RTSP 地址模板 + 完整流地址透传
  net_probe.py          socket 级连接诊断（超时/拒绝/认证/地址/无流 分类）
ui/
  main_window.py        主窗口：列表 + 网格、菜单/工具栏、窗口几何记忆、全屏
  camera_list.py        左侧摄像机列表（右键菜单 / 双击上墙）
  camera_dialog.py      添加/编辑摄像机
  video_grid.py         预览网格：布局、选中、分隔线、就地全屏
  preview_widget.py     单路预览控件：封装一个 VLC MediaPlayer
  layouts.py            按数量生成窗格布局（等分 / 1 大 + N 小）
tools/mock_cameras.py   模拟 HLS 摄像机（ffmpeg + http.server）
```

## 3. 关键设计决策

### 3.1 视频嵌入必须走 X11(xcb)
LibVLC 通过 `set_xwindow(X11 窗口 ID)` 把视频渲染进自建控件。若 Qt 使用 Wayland 平台，
`winId()` 不是 X11 窗口，VLC 会在 XWayland 另开窗口，表现为画面与界面错位/重叠。
因此 Linux 下只要存在 `DISPLAY`（含 XWayland）就强制 `QT_QPA_PLATFORM=xcb`
（`main.py`，可用 `EASYVIEW_QT_PLATFORM` 覆盖）。

### 3.2 每格只有一个原生窗口
`PreviewWidget` 以 `video_frame`（`WA_NativeWindow`）作为 VLC 渲染目标，鼠标交互在
其 `eventFilter` 中处理，**不再叠加透明捕获层**——避免每个格子出现多个堆叠原生窗口导致
无合成器的 X11 上画面残留。

### 3.3 网格由 QGridLayout 管理
布局切换与缩放交给 Qt（`VideoGrid.apply_layout`），不手工 `setGeometry` 原生窗口。
分隔线与选中高亮画在 Qt 控件间隙中（原生窗口矩形之外），保证可见且与布局一致。

### 3.4 全屏「就地」而非重挂顶层
把含原生 VLC 子窗口的控件 `setParent(None)` + `showFullScreen()`，在平铺式 Wayland
（Hyprland 等，经 XWayland）会被拒绝。故全屏分两种，均**直接对主窗口 `showFullScreen`**：
- 单路全屏（双击窗格）：网格内只显示该路，隐藏框架；
- 视窗全屏（`F11`）：保留全部窗格，隐藏框架。

### 3.5 流地址解析优先级
`Camera.rtsp_url()`：HTTP 协议直接用 `stream_uri`；否则 `stream_uri` 非空则用它，
再否则按 `vendor` 从 `rtsp_templates` 构造。

## 4. 连接诊断分类

`core.net_probe.diagnose_connection` 返回状态码，供 UI 提示：

| 码 | 含义 |
|----|------|
| `ok` | 可达且鉴权/流正常 |
| `dns` | 无法解析主机 |
| `refused` | 连接被拒绝 |
| `timeout` | 网络超时 |
| `unreachable` | 网络不可达 |
| `auth` | 密码/鉴权错误 |
| `bad_url` | 地址或通道错误 |
| `bad_config` | IP/地址未填写 |
| `error` | 其它错误 |

RTSP 走 TCP 探测 + `DESCRIBE`（支持 Basic/Digest）；HTTP 走 GET。

## 5. 已知限制

- 真实多厂商 RTSP 拉流未在全部环境端到端验证（依赖完整 VLC 的 live555 插件）。
- 拖动分隔线调整占比未实现（曾引发原生窗口残影），仅保留预设分屏。
- macOS 未适配测试。
