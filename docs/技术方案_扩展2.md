# EasyVIEW 技术方案（扩展二）：抓拍 / 原生巡航 / 录像计划

在已有「摄像机管理 + ONVIF + PTZ + 多厂商 RTSP + 本地录像 + 凭据加密」基础上，新增三项能力。本文明确各功能的**触发方式、调用接口、参数配置、数据存储**。

技术栈不变：Python 3 + PyQt6 + LibVLC；新模块均为纯逻辑层（`core/`）+ 面板层（`ui/`），与既有架构无缝衔接。

---

## 一、截图抓拍（Snapshot）

### 1.1 触发方式
| 方式 | 入口 | 说明 |
|---|---|---|
| 手动 | 工具栏「抓拍」按钮 / 快捷键 `S` | 捕获**当前激活预览路**（`grid.active_widget`）画面 |
| 定时 | 「截图抓拍」停靠窗，设间隔后「开始定时」 | 后台线程按 `interval` 秒周期抓拍激活路 |

### 1.2 调用接口
通过 LibVLC 的 `MediaPlayer.video_take_snapshot(num, file_path, width, height)`：
- `num=0`（视频输出序号）
- `file_path`：目标文件，扩展名决定格式（`.jpg`/`.png`）
- `width/height=0`：按视频原始分辨率保存

封装位置：
- `ui/preview_widget.py::PreviewWidget.take_snapshot(path)` —— 对单个预览控件暴露快照能力
- `core/snapshot.py::SnapshotManager.capture(player, camera_id, label)` —— 单次抓拍 + 落库
- `core/snapshot.py::SnapshotManager.start_timed(...)` / `stop_timed(...)` —— 定时循环（独立 daemon 线程，按 `player_provider()` 实时取 player）

### 1.3 参数配置（`SnapshotManager.configure`）
- `fmt`：`jpg` / `png`（默认 jpg）
- `quality`：jpg 质量 1..100（默认 90，png 忽略）
- `interval`：定时抓拍间隔秒（面板 `QSpinBox`，≥1）
- 文件名：`snapshots/cam{id}/YYYYMMDD/HHMMSS_{ms}.{ext}`，`label` 写入 DB 标签列

### 1.4 数据存储
- **文件**：`<DATA_DIR>/snapshots/cam{id}/<日期>/<时间戳>.{ext}`
- **索引**：`snapshots` 表（`camera_id, taken_at, path, width, height, label`）
- 检索：`search_snapshots(camera_id, date)`；删除：`delete_snapshot(sid)`（同步删文件）
- UI 历史列表双击用 `QDesktopServices` 调系统查看器打开

## 二、设备原生巡航轨迹（Vendor SDK）

### 2.1 触发方式
| 操作 | 入口 | 行为 |
|---|---|---|
| 上传到设备 | 「云台」面板「原生巡航轨迹」组「上传到设备」 | 逐点调用设备 SDK 把预置位写入设备巡航路线（设备端持久化） |
| 运行 | 「运行」按钮 | 下发「开始巡航」指令，**由设备自身执行轨迹**（客户端不轮询） |
| 停止 | 「停止」按钮 | 下发「停止巡航」 |
| 清除 | 「清除」按钮 | 删除设备端该巡航路线 |
| 配置存取 | 「保存/加载/删除配置」 | 轨迹点镜像存本地 `cruise_tracks` 表，便于复用 |

### 2.2 调用接口（按厂商选择控制器，见工厂 `get_cruise_controller`）
- **海康 HCNetSDK**（`core/vendor_sdk.py::HikvisionSDK`）
  - `NET_DVR_Login_V30` 登录取 `lUserID`
  - `NET_DVR_PTZCruise(lUserID, lChannel, dwPTZCruiseCmd, byCruiseRoute, byCruisePoint, wInput)`
  - 命令枚举（以 `HCNetSDK.h` 为准，常见值）：`30` 填充预置点 / `31` 删点 / `32` 开始巡航 / `33` 停止 / `34` 删除路线；`wInput`=停留秒
- **大华 dhnetsdk**（`core/vendor_sdk.py::DahuaSDK`）
  - `CLIENT_Login` 取 `lLoginID`
  - `CLIENT_PTZCruise(lLoginID, nChannel, dwPTZCruiseCmd, byCruiseRoute, byCruisePoint, byCruiseTime, dwStopTime, waiteTime, cb, dwUser)`
  - 命令枚举（以 `dhnetsdk.h` 为准，常见值）：`9` 填充 / `10` 删点 / `11` 运行 / `12` 停止 / `13` 删除；`byCruiseTime`=停留秒，`dwStopTime`=速度档
- **兜底 ONVIF**（`core/cruise.py::GenericCruiseController`）
  - 运行环境无厂商 SDK 时，自动回退 `OnvifDevice` 预置位轮巡（`start_cruise`），功能不中断

### 2.3 参数配置（`CruiseTrack.points`）
每个巡航点：`{preset_no(设备原生预置位号 1..N), dwell(停留秒), speed(速度档)}`
- 海康：`preset_no→byCruisePoint`，`dwell→wInput`
- 大华：`preset_no→byCruisePoint`，`dwell→byCruiseTime`，`speed→dwStopTime`
- 路线号 `track_no`（1..16），名称 `name`

### 2.4 数据存储
- **设备端**：轨迹由设备原生存储（核心能力），客户端只下发指令
- **本地镜像**：`cruise_tracks` 表（`camera_id, track_no, name, points_json, created_at`）
- 控制器登录会话按 `(ip,port,user)` 缓存单例，避免重复登录

> 部署注意：HCNetSDK/dhnetsdk 为 C 动态库，**非 pip 依赖**，需用户自行部署（Win 放 `HCNetSDK.dll`/`dhnetsdk.dll` 到 PATH，Linux 放 `.so` 到 `LD_LIBRARY_PATH`）。`cruise` 命令枚举值务必与所用 SDK 头文件核对，不同固件版本可能微调。

## 三、录像计划（定时 + 移动侦测）

### 3.1 触发方式
| 模式 | 引擎行为 | 触发源 |
|---|---|---|
| 定时 `schedule` | 后台线程每 `eval_interval`(默认15s) 轮询计划；当前时间落入「星期位掩码 + 起止分钟」窗口且未录制 → 自动开始；离开窗口 → 自动停止 | 时间条件 |
| 移动侦测 `motion` | 后台线程每 `sample_interval`(默认1s) 为每路 motion 计划抓快照做帧差；连续 `min_consecutive` 帧判为有变化 → 触发录像 | 画面变化 |

录像引擎统一入口：`PlanEngine`（`core/recording_plan.py`），由「录像计划」停靠窗「启动计划引擎」按钮启停。

### 3.2 调用接口
- 录像统一走 `RecorderManager.start(camera, segment_seconds, trigger, plan_id)`
- 定时判定：`PlanEngine._eval_schedules()` —— 仅停止**本引擎发起**的录像（不影响手动/移动录像）
- 移动侦测：`PlanEngine._eval_motion()` —— 为每路开独立子码流播放器（`:vout=vdummy`，仅为解码帧供快照），快照大小帧差启发式判定；带 `pre_seconds` 预录缓冲、`post_seconds` 后录缓冲、`min_duration` 最短时长
- **备选移动源**（文档化集成点）：设备原生移动告警 —— ONVIF `CreatePullPointSubscription`/`PullMessages` 事件订阅，或厂商 SDK 告警回调，可直接调用同一套 `rm.start(..., trigger='motion', plan_id=...)` 逻辑

### 3.3 参数配置（`recording_plans` 表字段）
**通用**：`enabled`, `mode`, `stream_type`(默认 sub 子码流，降低并发压力), `segment_seconds`
**定时**：`weekdays`(位掩码 bit0=周一..bit6=周日), `start_min`/`end_min`(0..1439，支持跨夜)
**移动侦测**：`sensitivity`(1..10), `min_consecutive`(连续帧数), `pre_seconds`, `post_seconds`, `min_duration`

窗口判定（`_in_window`）：`weekdays` 含当日星期 且 当前分钟 ∈ [start_min, end_min)（start>end 视为跨夜）。

### 3.4 数据存储
- **计划配置**：`recording_plans` 表（上述全部字段 + `created_at`）
- **录像段**：沿用 `recordings` 表，新增两列用于溯源：
  - `trigger`：`manual` / `schedule` / `motion`
  - `plan_id`：发起该段录像的计划 id（0=非计划）
- 写库由 `playback.add_recording(..., trigger, plan_id)` 完成，`RecorderManager` 在 `on_segment` 回调中携带来源

## 五、已知约束与后续建议
1. **厂商 SDK 命令枚举**需以真实 SDK 头文件核对；本实现已按常见取值给出并标注。
2. **移动侦测**默认快照帧差启发式，适合参考；生产建议 OpenCV 帧差或设备原生告警，精度与性能更佳。
3. **并发 RTSP 数**：多路 motion 各开一路子码流，易受设备并发限制，建议统一走子码流。
4. **巡航轨迹**最终以**设备端**为准；本地 `cruise_tracks` 为配置镜像，重装/换机后可重新「上传到设备」。
5. 本环境无 GUI/设备/网络，代码仅完成 `py_compile` 语法校验，未在真机运行；上机后建议依次验证：抓拍 → 原生巡航（需部署 SDK）→ 录像计划引擎。
